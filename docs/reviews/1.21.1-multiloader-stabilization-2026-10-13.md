## 2. C1 — результат и численные гарантии

Обход использует целые номера циклов и локальные окна в double. Math.fma вычисляет остаток без предварительного округления огромной абсолютной границы; округлённый quotient корректируется по остатку. Каждый локальный интервал обязан строго двигаться, а индекс цикла меняется на ±1. Empty events/zero length/нулевое движение обход не запускают.

Graph playback хранит double clocks, проверяет конечность и невозможность дальнейшего продвижения. Sampling/phase сохраняют остаток до float conversion. Все graph playback times не оборачиваются одной длительностью: blend samples сохраняют собственные durations. Исходный четырёхкомпонентный EventTrack и tick API сохранены; controller dispatch использует tickPrecise/PreciseEventTrack. PLAY_ONCE/HOLD raw arithmetic не менялась.

Forward: zero marker на departure, end marker на arrival. Reverse: descending order, zero на arrival, end на departure предыдущего цикла. На первом tick raw reverse начальный end marker по-прежнему исключён; после wrap он срабатывает. Epsilon range для end marker удалён, поэтому соседнее near-end событие не дублируется.

Патологические входы не обрезаются: nonfinite times, неразличимые clocks/indices и слишком большой объём callbacks дают IllegalArgumentException с диагностикой. Предел 1,048,576 callbacks на один dispatch проверяется до любых callbacks; это явный fail-fast для непроцессируемого client tick. Все допустимые события меньшего диапазона обходятся, включая несколько циклов. Integer phase support ограничен индексами менее 2^53.

**25 JUnit cases — PASS**, каждый с timeout 5 s в отдельном thread. Дополнительно 2000 случайных окон сравниваются с независимым absolute-event reference.

## 3. H14 Performance

Оборудование: GTX 1660 Ti 6 GiB, driver 615.71.09, Ryzen 5 3600X, Java 21.0.11, Minecraft 1.21.1; Fabric Loader 0.19.5 / NeoForge 21.1.216. Текущий стандартный MC context — OpenGL 3.2 с ARB_timer_query. Размер монитора 1920×1080.

Парные GPU timestamps собираются асинхронно после QUERY_RESULT_AVAILABLE; нет glFinish, pixel readback или CPU Java-call timing в измеряемых кадрах. Root GPU elapsed может включать промежутки между host submissions, query overhead и влияние desktop GPU work. Это elapsed intervals команд, а не profiler GPU busy occupancy. Один прогон/80 samples не доказывает одинаковое время на всех GPUs/drivers.

Offscreen: 24 сценария на loader, 32 warmup + 80 samples, размеры 1080p/1440p/4K, 0/1/16/128 overlapping quads. Real world: 6 сценариев на loader, 64 warmup + 80 samples, фиксированная spectator camera/stone fixture, render distance 6. World root — GameRenderer.render, включает world/UI rendering, исключает final presentation/blit/swap. Profiling window скрыт; live GL framebuffer продолжает рендериться.

Payload: 4×(RGBA16F 8 + R16F 2 + R32F 4)=56 bytes/pixel; Fabulous добавляет RG32F 8 bytes/pixel. Это capacity textures, без driver padding/tiling/allocator overhead. Native depth channel-size footprint тоже логический. CSV driver_vram_delta_mib — измеренная разница global NVX available VRAM до создания fixture и после прогрева; включает main/native targets, arena, shaders/query storage и другие allocations, зависит от residency/background. Не выдаётся за изолированный exact OIT footprint.

Steady OIT texture allocations — **0** на всех 60 rows; fingerprints GPU objects/capacities стабильны. В world OIT frames наблюдается **1 glBufferData call** для существующего deformation stream; это не новая metadata allocation. Persistent instance/indirect buffers и multi-draw indirect активны в nonempty scenes. Пустые OIT frames: 0 depth/accumulation/metadata/compositor и 0 OIT fullscreen draws, включая кадр после активной геометрии с retained resources. Vanilla transparency chain в Fabulous продолжает свои 2 fullscreen passes. VRAM может оставаться зарезервированной до cleanup/resize.

Resize/reload: функциональные H14 regressions повторены на обоих loaders — 38 GPU cases + мировые Fancy/Fabulous/rain/occlusion checks после одного reload и resize, с проверкой pixels, depth и GL restoration. По коду при изменении size/depth attachment пересоздаются 12 базовых textures + lazy metadata в Fabulous; отдельное cold GPU timing/пиковая VRAM resize/reload не измерялись.

Вывод для этого оборудования: 1080p one-quad world overhead нового packing/compositor — около 0.22–0.23 ms packing плюс 0.22 ms final composition. Относительно Fancy composition дополнительный meta+compositor вклад около 0.28 ms в этой мировой fixture. В 4K offscreen meta+compositor требуют примерно 1.93 ms Fabric / 2.70 ms NeoForge; сравнительный новый вклад относительно Fancy composition — примерно 1.15 / 1.91 ms. Native transparency chain и существующие depth/accumulation расходы указаны отдельно. Stress 128 полноэкранных quads превышает frame budget в основном из-за существующих depth/accumulation (offscreen total ~192 ms); это controlled worst-case, не обычная игровая нагрузка.

Production OIT сохранён. Потенциальные отдельные оптимизации, **без измеренного выигрыша и без применения сейчас**:

| Вариант | Стоимость/ожидаемый эффект | Сложность/риски |
|---|---|---|
| Паковать 2 слоя в один RGBA32F pass, reuse одной texture | 4→2 packing passes; total byte traffic примерно тот же; +8 bytes/pixel VRAM. Верхний предел выигрыша — измеренная metadata часть, реальный выигрыш неизвестен | Средняя: component/layer selection, state restoration; все H14 pixels обязательны |
| GPU conditional rendering для действительно пустых peeled layers | Может убрать accumulation/packing/composition отсутствующих слоёв; counter/query cost неизвестен | Высокая: pipeline stalls, правильность current-frame decisions. Нельзя skip по stale previous-frame result |
| Pool для resize targets | Возможный эффект только на resize; steady-state уже reuse/0 texture realloc | Средняя: VRAM retention и depth identity; cold profiling нужно отдельно |

Не снижать число математических OIT layers/precision ради FPS; не менять формулу композиции. Любую реализацию начинать с отдельного controlled A/B benchmark и H14 regression.

Недостоверные промежуточные profiling runs (GUI/world contamination и стартовый GUI timeout) не включены в таблицы; после исправления bootstrap/изоляции все четыре серии завершились с PASS.

## 4. NeoForge smoke

Assertion расположен в SmokeHarness, вызван из GameRenderer TAIL через SmokeRenderMixin. Реальный draw path: LevelRenderer visible sections/frustum → BlockEntityRenderDispatcher.render → PBlockRenderer.render/trueSubmit → resolveBoneRender/submitBone; observer стоит в TestBlockEntityRenderer.resolveBoneRender. Старый fixture ставил блок относительно текущего player, отправлял server task без ожидания client acknowledgement и через 30 client ticks требовал глобальный BER counter. Camera/frustum/occlusion/готовность блока не контролировались.

Контролируемое воспроизведение: client block `(11,140,14)`, type/state верны, removed=false, TestBlockEntityRenderer зарегистрирован; first-person camera `(10.5,141.62,10.5)`, yaw180, frustumVisible=false, calls0 → **тот же Original block entity renderer must run**. Видимая фиксированная third-person camera `(10.5,141.62,6.5)`, yaw0: frustumVisible=true, реальные calls>0 на обоих loaders.

Конкретный путь ложного failure — зависимость assertion от камеры/frustum. Историческая камера исходного запуска не восстановлена (Test не открывался); не утверждается, что все возможные причины старого counter0 доказаны. Новый fixture также устраняет race готовности server/client блока и spectator/item условия. IDE debug launches не предоставили сохраняемой активной session/logpoint evidence; вывод основан на source call chain, контролируемых probes и assertions, а не на заявленном debugger наблюдении. Временные agent breakpoints удалены, все 3 пользовательских breakpoints сохранены. Registration adapters библиотеки не менялись; настоящего NeoForge renderer-registration дефекта в controlled scene не обнаружено.

## 5. Lifecycle

| Loader | Explicit cleanup | Natural disconnect | Suppressed-hook negative control |
|---|---|---|---|
| Fabric | PASS | PASS, 1 observed штатный callback | EXPECTED FAIL, живой GPU buffer |
| NeoForge | PASS | PASS, 1 observed штатный callback | EXPECTED FAIL, живой GPU buffer |

Natural branch не вызывает PulseRuntime.disconnected вручную. Перед disconnect managers/resources repopulated; sentinel instance/singleton исключает vacuous assertion после chunk removal. Проверены geometry/instance/indirect/deformer buffers, OIT texture IDs/FBO, CPU/GPU deformation caches, renderer geometry registry и instance/singleton/player managers. Explicit cleanup имеет отдельную фазу и marker, не служит fallback. При отсутствующем callback есть deadline и явное assertion; negative control подавляет все штатные cleanup entries только в natural phase, сохраняя explicit test.
