## H17 — исправление и side/thread audit

`BlockEntityMixin` находится в `client` секции common mixin config. Эта секция ограничивает физическую среду загрузки, а не `BlockEntity.level`: один трансформированный класс используется ClientLevel и ServerLevel интегрированного сервера.

В исходниках Minecraft 1.21.1 проверены `BlockEntity.setRemoved` и `LevelChunk.removeBlockEntity`/`clearAllBlockEntities`: они не ограничены client side. `removeBlockEntity` вызывает `setRemoved()` как после разрушения серверного блока, так и в клиентском chunk. Следовательно, прежний injection на HEAD без side guard обращался к shared `ObjectOpenHashSet` на серверном потоке, даже когда server owner никогда не регистрировался: `removeIf` всё равно проходит коллекцию.

Внесено в [BlockEntityMixin.java](../../common/src/main/java/com/arcanc/pulselib/content/mixin/BlockEntityMixin.java#L23):

```java
@Nullable Level level = ((BlockEntity)(Object)this).getLevel();
if (level != null && level.isClientSide())
{
	InstanceAnimationManager.removeManager(this);
}
```

Managers не перенесены на сервер; коллекция не заменена concurrent-структурой; identity сравнение в removeManager сохранено. ClientLevel unload по-прежнему проходит injection, пока level установлен. Detached/null-level owner пропускается; global cleanup при смене мира остаётся независимым механизмом.

Дополнительные пути проверены:

| Путь | Сторона/поток и результат |
|---|---|
| PEntityRenderer/PBlockRenderer → addManager | Клиентские render callbacks; registration не добавлена на server |
| PLibAnimationTicker → instance/singleton/player tick | Только ClientLevel в NeoForge LevelTickEvent; Fabric START_WORLD_TICK |
| NeoForge EntityLeaveLevelEvent → removeManager | Уже есть `event.getLevel().isClientSide()`; интегрированный server исключён |
| Fabric ClientEntityEvents.ENTITY_UNLOAD | Событие ClientWorld; server instance не проходит |
| Fabric setLevel/disconnect → PulseRuntime | Клиентский setLevel и client.execute; PulseRuntime.assertOnRenderThread сохранён |
| NeoForge LevelEvent.Unload → PulseRuntime | Только ClientLevel; server unload не чистит GL/client registries |
| Player API (M-P5), camera shake (L32), публичные manager методы | Client-only usage не означает thread-safe external API; library caller с ServerPlayer не найден. Рекомендуется документирование/defensive guard отдельным контрактным решением |
| tests/testmod SmokeServerMixin:48–49 | Прямые removeManager на dedicated server остаются **тестовым** обращением к клиентскому классу. Это не путь штатной библиотеки/интегрированного сервера (`isDedicatedServer` guard). Не исправлено: source scope ограничен H17; fixture следует отделить от проверки server plugin isolation |
| tickAll callbacks (L33) | Возможна single-thread reentrancy; H17 side guard её не исправляет и не требует concurrent collections |

Проверка точного тела mixin в `/tmp` со stub BlockEntity/Level и observer manager: исходный код дал 2 registry calls от `Server thread` (server и null-level), новый — 0. В обоих вариантах client owner удалён одним client call. Stubs моделируют injection inheritance; **это не** измерение реальной concurrent set corruption. Сборка/реальный запуск подтвердили применимость mixin к Minecraft 1.21.1; Fabric singleplayer два мира прошёл без выявленных cross-thread ошибок. Искусственная race/CME не провоцировалась.

Минимальный regression для постоянного suite: server Level и null Level не вызывают removeManager; client Level вызывает; реальный client chunk unload удаляет зарегистрированный owner; смена мира очищает остальные managers и GL resources через естественный hook. Риск patch низкий: detached managers больше не удаляются этим injection, но global cleanup сохранён. Приоритет H17 до patch — P1; работа завершена.

## H8 — fail-fast и диагностика

`PModelCache.loadModels` сохраняет exceptional futures через `CompletableFuture.allOf`; malformed/missing resources должны останавливать загрузку. Никаких `handle`, `exceptionally`, empty replacements или silent continuation не добавлено.

| Ошибка | ID/source/cause в текущей диагностике |
|---|---|
| Нет зарегистрированного loader | modelId и loaderId уже есть |
| Нет физического ресурса | modelId и список candidate resource IDs уже есть |
| IOException Gecko/glTF | source и modelId уже есть; exception сохранён как cause |
| Loader вернул другой ID | ожидаемый/полученный modelId и loaderId уже есть |
| Runtime JSON/Molang/jgltf exception | Cause распространяется, но catch только IOException не добавляет modelId/source |
| Baking exception | Context добавляется в части bakePrimitive; ранний empty textureReference throw проходит вне этого блока |

Предлагаемое **отдельное** улучшение: в boundary выбранного model/sidecar resource добавить contextual exception с modelId, source и cause для runtime parse failures. Не менять факт exception и не отклонять original cause. Sidecar source нужен отдельно от основной модели. Это улучшение диагностики, не «исправление H8».

## H14 — фактические passes Minecraft 1.21.1

Проверены локальные vanilla sources/resource JAR для Minecraft 1.21.1 и NeoForge 21.1.216, а также Fabric injection points. Основной порядок `LevelRenderer.renderLevel`: opaque terrain → vanilla entities/block entities → AFTER_BLOCK_ENTITIES → translucent terrain → particles → AFTER_PARTICLES → clouds → rain/weather → AFTER_WEATHER → Fabulous transparency chain (если включена) → конец level pass.

| Этап | Fast/Fancy | Fabulous |
|---|---|---|
| Opaque vanilla/main depth | Main target | Main target |
| PulseLib SOLID_BLOCKS | Flush после block entities, текущий main target | То же, до copies main depth в late targets |
| Translucent terrain | Main target; default layer writes depth | Translucent target с copy main depth |
| Particles | Текущий main; у NeoForge solid particles имеют ранний отдельный проход | Particles target clear + copy main depth; AFTER_PARTICLES выполняется до сброса PARTICLES_TARGET |
| PulseLib ENTITIES + TRANSLUCENT_BLOCKS | Standard draws в текущий target, затем OIT passes | Standard draws в particles target при соответствующем RenderType state; OIT begin по умолчанию получает main target depth |
| OIT depth/accumulation | Собственный FBO; attachment main depth, depth test on, depthMask false; peel layer depth хранится в color texture | Та же собственная система; это ещё не weather depth |
| Clouds/weather | После накопления OIT; weather в main | Отдельные clouds/weather targets, weather clear ранее не копирует main depth |
| PulseLib composite | После weather в main; depth test off, depthMask false | После weather в weather target; те же depth settings |
| Vanilla transparency composite | Отсутствует | Сортирует main/translucent/itemEntity/particles/weather/clouds по соответствующим depth textures и alpha |

Сам факт `gl_FragDepth` в PulseLib composite shader при disabled depth test и depthMask=false не записывает depth attachment. Это установлено [OpenGL depth-mask semantics](https://registry.khronos.org/OpenGL-Refpages/gl4/html/glDepthMask.xhtml). Vanilla `transparency.fsh` сортирует weather color по **weather depth**, а не по PulseLib layer depth sampler. Поэтому пиксель с ненулевым OIT color, weather depth=1 и main opaque depth<1 — конкретный риск: main opaque layer при последующем blend может закрыть такую weather contribution. Однако rain мог ранее записать другую weather depth; несколько OIT layers имеют разные глубины; части world geometry могут рисоваться в другой target. Утверждение «невидимо поверх любой геометрии» без проверки этих состояний остаётся слишком широким.

Прогон Fabric Fabulous singleplayer прошёл, включая offscreen OIT pixels (504 partial-alpha) и reload. [Снимок тестовой сцены](evidence/fabulous-world.png) показывает снег/небо и демо-модели; `tube_texture` содержит alpha152/153. Снимок не изолирует один OIT pixel и не доказывает отсутствие/наличие дефекта depth-композиции. Не выполнялся контролируемый particles test, дождь/облака не сравнивались по depth attachments. Поэтому итог H14 — **POTENTIAL BUG / NOT REPRODUCED**, GL-код сохранён.

Следующая проверка: одна неподвижная прозрачная часть демо-блока пересекает края непрозрачного снега/камня и неба; затем smoke particles перед/за ней. На одинаковой камере Fast/Fancy/Fabulous снять main, particles, weather color+depth и OIT layer depths до/после composite. Если ненулевой OIT fragment исчезает именно из-за stale weather depth, это минимальный доказанный сценарий. Только после него выбирать depth-aware composition. Не применять глобальный `GL_ALWAYS/depthMask(true)` сейчас: он может перезаписать глубину rain и не выразит все OIT layers одним weather depth. Не заменять main depth particles depth без проверки opaque placement/H13.

## H15 — техническое заключение GUI/world

Модельные GUI helpers корректно immediate: `PLibHelper.renderModelInGui` → `PBakedModel.instantDraw` → `PBakedBone.instantDraw/drawMesh`; `PItemRenderer.trueSubmit` в `ItemDisplayContext.GUI` тоже вызывает `model.instantDraw` и возвращает до queue path. H15 к этим вызовам не относится. H16 — отдельная проблема самого immediate index upload.

`PEntityRenderer.render` → `trueSubmit` → `submitBone` → `PRenderQueue.submitEntityMesh` всегда выбирает ENTITIES. Minecraft 1.21.1 `InventoryScreen.renderEntityInInventory` вызывает `EntityRenderDispatcher.render` из GUI, включая arbitrary LivingEntity, затем `GuiGraphics.flush`: это flush vanilla BufferSource, не PulseLib frame compiler. Значит supported custom renderer действительно может попасть в очередь вне мирового прохода. TestMod регистрирует `TestEntityRender extends PEntityRenderer`; путь не требует воображаемого API.

| Сценарий | Вывод по текущему коду |
|---|---|
| Обычный world entity | Queue ENTITIES намеренна; batching/instancing/OIT сохранить |
| Inventory vanilla player | Body использует PlayerRenderer, не PEntityRenderer: старый общий тезис о невидимом player — FALSE POSITIVE. PulseLib automatic mesh attachment layer/held custom item могут отдельно queue ENTITIES |
| GUI preview custom entity | Если dispatcher выбирает PEntityRenderer, geometry deferred и не доступна GUI flush |
| Dispatcher вне level pass | Queue остаётся до соответствующего world stage/cleanup; текущие framebuffer/projection не фиксируются как offscreen destination |
| GUI без level | Для detached entity/model при успешном getModel manager/render path всё ещё queue; late stages отсутствуют. Риск роста зависит от active submissions и их lifetime, не от любого пустого GUI |
| Переход screen→world | Pending GUI matrices могут попасть в следующий world flush; precise ghost position не воспроизведён |

Рекомендуемое решение отдельной задачей: внутренний scoped render context WORLD/GUI/OFFSCREEN/FIRST_PERSON с `try/finally` и nested stack. WORLD выставлять вокруг настоящего world render pass; известные GUI adapters/InventoryScreen dispatcher wrapper задают GUI, offscreen callers — explicit scope. `mc.level != null`, `mc.screen != null`, `renderShadow` или `runAsFancy` не являются надёжными признаками: мир рисуется под GUI, а dispatcher используется и для offscreen previews.

Resolved bones/poses/materials должны выбирать draw backend: в WORLD — прежняя queue, GUI/OFFSCREEN — immediate на текущем framebuffer с текущим projection/state. Применить решение к entity render layers, automatic player mesh attachments и THIRD_PERSON/HEAD custom item paths, а не только к root mesh. Не просто вызвать `model.instantDraw` и потерять head positioning, layers/overrides/visibility. Неправильно flush ENTITIES из GUI: это смешает уже накопленные world calls. Frame reset полезен как защита stale commands, но не заменяет routing и не должен удалять legit late submissions.

Регрессии: все шесть сценариев, nested offscreen draw во время world pass, отсутствие level, исключение в layer, оба loaders, OIT world batching и обычный GUI item. Во время GUI размер WORLD compiler не меняется; immediate draw учитывает target/state; новый world frame не получает GUI-space instance. В этом задании исправление H15 не применено.

## Небольшой план расширения glTF

Это **future enhancement**, ничего ниже не реализовано и не включено в подтверждённый bug backlog.

1. Зафиксировать поддерживаемый экспортный профиль Blockbench и capability diagnostics. Unsupported external buffers/accessor/interpolation/material/skin/extension должны иметь model/source context и явный отказ; H8 fail-fast сохранить. Базовые golden assets: embedded indexed FLOAT/TRS/LINEAR bone models и используемые демо.
2. Независимый resource resolver для relative .bin/image URIs (H7), с ResourceManager/namespace ownership и закрытием streams. Отдельно type-aware accessors: componentType, normalized, stride, sparse при объявленной поддержке. На нём строятся BYTE→SHORT/INT indices (M-R1), quantized UV/rotations (M-D4), optional attributes/non-indexed synthesis (M-D1/M-D2). Не считать image URI автоматически atlas texture registration.
3. Node transform representation/scale/matrix и mesh-node animation (M-D5/M-D6); затем STEP и CUBICSPLINE samplers (M-D3). Bone matrices/scale должны быть согласованы с pose hierarchy и normals. STEP не зависит от matrix support; quaternion Hermite/normalization зависит от type-aware output decode и tangent representation.
4. Materials/scene/negative-scale winding и дополнительные extensions — отдельно от geometry minimum. Настоящее JOINTS/WEIGHTS skinning требует palette/inverse-bind matrices и новой renderer data layout; morph targets требуют дополнительной vertex storage/animation path. Эти работы зависят от accessor/node layers и возможностей CPU/GPU renderer, а не только JSON parser.

Не восстанавливать deprecated API и не добавлять обязательные зависимости ради этого плана.
